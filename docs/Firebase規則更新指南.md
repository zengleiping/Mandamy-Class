# Firebase 規則更新指南（曼米中文平台）

這份指南搭配同一個資料夾上層的 `firebase-rules.json`。照著做約 10 分鐘。**先備份舊規則再貼新的**，貼錯了隨時可以還原。

## 1. 這份規則做了什麼

| 項目 | 說明 |
|---|---|
| 只開放用到的路徑 | 平台、簡報、教材頁、時空膠囊、接力故事、聯絡簿等用到的路徑才開放，其他路徑一律關閉。 |
| 不能一次列出全部 | 不能一次讀出「所有班級代碼」「所有老師的平台資料」「所有房間」，只能用已知的 id 讀取。 |
| 班級代碼格式檢查 | `classCodes` 只能寫入格式正確的資料（4–10 碼英數字，並含老師、學校、班級資料）。 |
| 圖片大小上限 | 學生上傳的作業照片、課堂記錄截圖、作業附圖，每張最多約 900 KB，避免有人塞爆資料庫。 |
| 文字長度上限 | 聯絡簿文字、請假原因有長度上限。 |

## 2. 它「沒有」做到的事（請一定要知道）

目前整個系統用的是 Firebase「匿名登入」：每個打開網頁的人都是一個匿名使用者，老師、學生、家長在資料庫眼中沒有分別。所以：

- 規則**無法**限制「只有老師能改某份資料」「只有這位學生能交這份作業」。
- 平台裡的老師帳號、學生帳號、助教、家長連結，都是應用程式層級的限制，擋得住一般使用，擋不住懂技術、直接讀寫資料庫的人。
- `teacherAccounts` 仍然保留「已登入者可列出全部帳號」，因為簡報頁的老師管理功能需要。

要真正做到權限分明，需要把老師與學生都改成 Firebase 的正式登入（見第 6 節）。

## 3. 更新步驟

1. 打開 Firebase 主控台 → 你的專案 → **Realtime Database** → **規則**。
2. **先把現在的規則整段複製，貼到一個文字檔存起來**（這是你的還原點）。
3. 打開 `firebase-rules.json`，整份複製，貼進規則編輯器，覆蓋原本內容。
4. 按編輯器上方的「**規則遊樂場（Rules Playground）**」，依下面第 4 節逐項測試。
5. 都通過後，按「**發布**」。

## 4. 發布前的模擬測試（規則遊樂場）

在遊樂場選「已驗證」（Authenticated，任意 uid），逐項測試，結果要符合：

| 動作 | 路徑 | 預期 |
|---|---|---|
| 讀取 | `/classCodes/ABC234` | 允許 |
| 讀取 | `/classCodes` | **拒絕** |
| 讀取 | `/teacherPlatform` | **拒絕** |
| 讀取 | `/teacherPlatform/amy/schools` | 允許 |
| 寫入 | `/teacherPlatform/amy/notify/n1` | 允許 |
| 讀取 | `/rooms/1234` | 允許 |
| 寫入 | `/unknownPath/x` | **拒絕** |
| 寫入 | `/classCodes/abc` 資料 `{"t":"amy"}` | **拒絕**（格式不符） |
| 寫入 | `/classCodes/ABC234` 資料 `{"t":"amy","s":"y","tm":"s","c":"c"}` | 允許 |

再選「未驗證」（Unauthenticated）：讀寫任何路徑都應該被拒絕。

## 5. 發布後的驗證清單（約 5 分鐘）

用一台電腦、一支手機，依序確認：

1. 老師登入平台，首頁、課表、班級頁都載入正常。
2. 學生用班級代碼進班級，看得到老師開放的課次。
3. 老師開始上課，學生跟著進入房間，簡報和測驗可以操作。
4. 聯絡簿：老師公布作業，學生上傳照片和文字，老師看得到。
5. 時空膠囊連結可以建立並打開。
6. 教材庫新增一個課次並儲存。

任何一項失敗：馬上回到規則編輯器，貼回第 3 節步驟 2 存下來的舊規則，按發布，就回復原狀。然後把失敗的操作與畫面告訴我，我來修。

## 6. 之後想要「真正」的權限控制

做法是把登入改成 Firebase Authentication（電子郵件／密碼，或自訂 Token）：

1. 老師、學生各自有正式的使用者身分（uid）。
2. 規則改成用 `auth.uid` 比對：例如只有該班的老師與名單上的學生能讀寫聯絡簿，學生只能寫自己的繳交。
3. 老師與助教的身分，用資料庫裡的對照表或自訂 claims 區分。

這需要：在主控台啟用登入方式、重新設計所有路徑的規則、讓學生帳號改用正式登入，並重做遷移與測試，是一個獨立的階段（工作量大，建議另外排時間）。

## 7. 現在就能做的其他安全措施

- **限制 API 金鑰的使用網域**：Google Cloud 主控台 → API 和服務 → 憑證 → 你的瀏覽器金鑰 → 「應用程式限制」選「HTTP 參照網址」，加入 `https://zengleiping.github.io/*`。這樣別的網站拿走金鑰也用不了。
- **設定預算提醒**：Firebase／Google Cloud 的「帳單」→「預算與快訊」，設一個每月上限提醒，被濫用時早點知道。
- **確認匿名登入已啟用**：Authentication → Sign-in method → 匿名，必須是「已啟用」，平台才能運作。
- **定期備份**：平台首頁的「下載完整備份」每週做一次（平台會提醒你）。

## 8. 檔案儲存（Firebase Storage）規則——聯絡簿上傳檔案要用

聯絡簿 2.0 的檔案（老師的教材、學生繳交的 PDF／照片／錄音）放在 Firebase Storage，要加兩個路徑。**只要整份貼上就好**：

1. Firebase 主控台 → **Storage** → **規則**。
2. 把 `storage.rules`（本倉庫最上層）整份複製，貼上取代，按「發布」。這份已經包含你原本的 `teacherMedia` 規則，沒有拿掉任何東西。
3. 如果 Storage 還沒啟用，先按「開始使用」（選跟資料庫相同的地區即可）。

上限：每個檔案 30 MB。檔案的下載連結用「知道連結才打得開」的方式，沒有連結的人看不到。
