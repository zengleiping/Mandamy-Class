# Firebase 安全升級指南（規則 v2）

這次升級讓資料庫「分清楚誰是老師、誰是學生、誰是路人」。**規則不會自動生效**，要你在 Firebase 後台貼上才會啟用；貼之前平台照舊運作，不受影響。整個過程約 15 分鐘。

## 一、升級後的差別

| 角色 | 能做什麼 | 不能做什麼 |
|---|---|---|
| 路人（沒有班級代碼、沒有老師帳號） | 什麼都看不到 | 讀不到任何老師、學生資料 |
| 學生 / 家長（匿名登入） | 讀自己班的作業、公告、課表；交作業、留言、請假、考卷作答、Google 登入申請 | 讀不到別班資料、課堂記錄、老師帳號與密碼雜湊；不能改老師的回饋、請假核准、考卷批改狀態；不能刪班級代碼 |
| 老師 / 助教（Firebase 登入） | 讀寫自己的全部資料（助教可讀寫被加入的那位老師的資料） | 讀寫不到別位老師的資料 |
| 管理員 | 管理教師帳號（新增、停用、重設密碼） | 一樣讀不到別位老師的教學資料 |

## 二、依序操作

### 步驟 1：開啟「電子郵件／密碼」登入方式

1. Firebase 主控台 → 專案 **chinese-onlineboard** → **Build → Authentication → Sign-in method**。
2. 點 **Email/Password（電子郵件／密碼）**，把第一個開關（Enable）打開，**第二個「Email link（無密碼登入）」不要開**，按 **Save**。
3. 原本的 **Anonymous（匿名）** 和 **Google** 要保持開啟，不要關。

> 老師輸入的還是原本的「帳號＋密碼」，程式會在背後自動建立對應的 Firebase 帳號（信箱格式 `帳號@teacher.mandamy.app`，不是真的信箱，不會寄信）。

### 步驟 2：每位老師／助教各登入一次（先登入再貼規則）

1. 用電腦或 iPad 打開 `https://zengleiping.github.io/Mandamy-Class/app.html`。
2. 用**管理員帳號**登入（輸入原本的帳號密碼）。這一次登入會自動「認領」帳號。
3. 其他老師、助教也各自登入一次（只要一次；之後正常使用）。**沒登入過的人，在步驟 3 之後仍然可以登入並自動認領，所以不用急著一次全部完成。**
4. 確認方式：Firebase → Authentication → **Users**，會看到 `amy@teacher.mandamy.app` 這類帳號。

> **重要：** 沒有登入過的老師帳號，在認領之前是「誰先用這個帳號名稱註冊就是誰的」。所以請先自己登入認領，不要拖太久；用不到的舊帳號請在簡報頁「教師帳號管理」刪除。

### 步驟 3：貼上規則 v2

1. Firebase → **Realtime Database → 規則（Rules）**。
2. **先把目前整段規則複製貼到記事本存檔**（還原用）。
3. 打開檔案 `firebase-rules-v2.json`，整份複製，貼進規則編輯器覆蓋原本內容。
4. 按 **發布（Publish）**。
5. 發布成功後立刻做下面「三、檢查清單」。

### 步驟 4（建議）：每月備份

平台每次開啟都會自動下載備份檔，放在「下載」資料夾即可。

## 三、檢查清單（貼完規則馬上做）

| 動作 | 預期 |
|---|---|
| 老師重新整理平台頁面 | 直接進入（不用重新輸入密碼） |
| 老師登出再登入 | 密碼正確進入、錯誤會顯示「帳號或密碼錯誤」 |
| 開簡報頁 `slides/practice.html`、教材頁 | 同一個瀏覽器已登入就不用再登入 |
| 另一個瀏覽器或手機開學生連結 | 能進班級、看作業、交作業 |
| 家長連結 | 能看到孩子的狀況 |
| 老師看到學生剛交的作業 | 看得到 |

## 四、出問題怎麼辦（還原）

規則貼上去**馬上**可以還原：Realtime Database → 規則 → 貼回舊規則（步驟 3 存的記事本，或本專案的 `firebase-rules.json`）→ 發布。還原後一切回到升級前的狀態；已經建立的老師 Firebase 帳號不影響使用。

## 五、常見狀況

- **管理員重設別位老師的密碼**：在簡報頁「教師帳號管理 → 編輯」輸入新密碼即可，對方下次用新密碼登入，系統會自動重新認領。
- **管理員自己改密碼**：同一個畫面，需要「剛登入不久」；如果提示請登出再登入，照做一次即可。
- **管理員自己忘記密碼**：告訴我，我幫你產生新的密碼雜湊，並教你在後台清除舊的認領紀錄（Authentication → Users 刪除該帳號；資料庫 `teacherAccounts/帳號/uid` 與 `uidMap` 對應項刪除）。
- **老師換了裝置**：直接用帳號密碼登入即可。
- **學生看到「連線失敗」**：請把學生的班級連結與時間告訴我，我查規則是否擋到了。

## 六、這次升級「沒有」解決的事（請知道）

| 項目 | 說明 |
|---|---|
| 學生之間的冒名 | 學生用「名字」進班，沒有個人密碼的班級（沒有開學生帳號）裡，知道班級代碼的人理論上可以用別人的名字交作業。開學生帳號或綁定 Google 可降低風險，資料庫層級無法防止。 |
| 學生帳號密碼雜湊 | 知道班級代碼與學生名字的人，技術上可以讀到該生的密碼雜湊（加鹽、10 萬次運算，但密碼短仍可能被破解）。 |
| 課堂房間 | `rooms` 等即時課堂路徑維持「知道房間代碼就能進入」，與升級前相同；考卷房間內的作答與分數由前端計算，懂技術的學生理論上可以改自己的成績，所以重要的成績請以老師批改後的結果為準。 |
| 時空膠囊／接力故事 | 維持原本的開放程度（外部頁面也在用，改動會讓它們壞掉）。 |
| 課表 | 學生端可讀整份課表（為了顯示下次上課時間），內容包含其他班級的上課時間。 |
| 註冊 | Firebase 的「電子郵件註冊」保持開啟（匿名登入需要），所以認領要趁早做（步驟 2）。 |
| 儲存空間（照片、檔案） | `storage.rules` 沒有變動。 |

## 七、規則重點速查（給日後維護）

- 老師身分判斷：`uidMap/{Firebase uid}` 對應到老師帳號；助教看 `teacherPlatform/{老師}/assistants/{助教}` 是否存在。
- 停用的帳號（`disabled`）即使還有 Firebase 登入也讀寫不到資料。
- 認領：`teacherAccounts/{帳號}/uid` 只能在「尚未認領」且登入信箱與帳號相符時寫入；管理員重設密碼時 `authGen`＋1，信箱變成 `帳號.g1@teacher.mandamy.app`，舊身分作廢。
- 學生可寫入範圍：`hwSubs`（不含 `fb`、`fbAt`、`ov`）、`hwFiles`、`leave`（只能新增、狀態只能是 pending）、`notify`（只能新增）、`examAttempts`（作答中／重考狀態才可寫，且只能寫成作答中或已交卷）、`googleLinks`（只能寫自己的 uid，且不能自己設成 approved）、`bingo`、`studentAccounts`、留言（只能新增）。
